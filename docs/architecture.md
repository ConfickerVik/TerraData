# Архитектура системы

TerraData спроектирована как модульный сервис с четким разделением между слоем API, слоем сервисов и ML-компонентами.

## Диаграмма компонентов

```text
[ Клиент ] <---> [ FastAPI API ] <---> [ Слой сервисов ] <---> [ Росреестр / НСПД ]
                                              |
                                      [ ML Модель капчи ]
                                              |
                                      [ pdfkit / wkhtmltopdf ]
```

## Детальный анализ слоев

### 1. Слой API (`app/api/`)
Обрабатывает циклы HTTP-запросов и ответов. Использует модульные роутеры FastAPI для разделения логики:
- **Rosreestr API**: Данные об объектах и поиск.
- **NSPD API**: Пространственные данные и кадастровая стоимость.
- **Converter API**: Генерация PDF-документов.

### 2. Слой сервисов (`app/services/`)
Содержит основную бизнес-логику:
- **RosreestrClient**: Управление сессиями, обход блокировок и автоматизация работы с ЛК Росреестра.
- **NspdClient**: Интеграция с API НСПД для извлечения геометрии и детальных карточек объектов.
- **CoordsConverter**: Математический модуль для перевода координат из проекции Web Mercator (EPSG:3857) в WGS 84 (EPSG:4326) и расчета центроидов объектов.
- **RosreestrPdfConverter**: Оркестрация процесса XML $\rightarrow$ HTML $\rightarrow$ PDF.

### 3. ML Компонент (`app/models/`)
Модель на базе Keras (`pred.keras`), обученная для OCR (оптического распознавания символов) специально для капч Росреестра. Использует декодирование CTC (Connectionist Temporal Classification) для обработки текста переменной длины.

### 4. Внешние интеграции
- **ЛК Росреестра**: Источник данных и сервис трансформации XML.
- **API НСПД**: Источник пространственных данных и кадастровой стоимости.
- **wkhtmltopdf**: Движок для рендеринга HTML в PDF.
