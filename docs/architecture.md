# Архитектура системы

TerraData спроектирована как модульный сервис с четким разделением между слоем API, слоем сервисов и ML-компонентами.

## Диаграмма компонентов

```text
[ Клиент ] <---> [ FastAPI API ] <---> [ Слой сервисов ] <---> [ ЛК Росреестра ]
                                             |
                                     [ ML Модель капчи ]
                                             |
                                     [ pdfkit / wkhtmltopdf ]
```

## Детальный анализ слоев

### 1. Слой API (`app/api/`)
Обрабатывает циклы HTTP-запросов и ответов. Использует роутеры FastAPI для разделения логики данных Росреестра и логики конвертации.

### 2. Слой сервисов (`app/services/`)
Содержит основную бизнес-логику:
- **RosreestrClient**: Управляет сессиями, рандомизирует User-Agent для обхода блокировок и обрабатывает логику повторов при решении капчи.
- **RosreestrPdfConverter**: Координирует многошаговый процесс XML $\rightarrow$ Загрузка $\rightarrow$ HTML $\rightarrow$ PDF.

### 3. ML Компонент (`app/models/`)
Модель на базе Keras (`pred.keras`), обученная для OCR (оптического распознавания символов) специально для капч Росреестра. Использует декодирование CTC (Connectionist Temporal Classification) для обработки текста переменной длины.

### 4. Внешние интеграции
- **ЛК Росреестра**: Целевой бэкенд.
- **wkhtmltopdf**: Движок, который рендерит HTML-строки в профессиональные PDF-документы.
