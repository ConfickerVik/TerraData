# Дорожная карта проекта: TerraData

## 🎯 Цель проекта
Создание комплексной системы анализа недвижимости, которая получает данные из Росреестра, переводит XML-выписки в официальные PDF, обогащает информацию данными из НСПД (пространственные данные) и ФИАС (адресный реестр), а также определяет принадлежность объекта к конкретному судебному участку через СУДРФ.

---

- [x] Настройка структуры проекта (`app/`, `data/`).
- [x] Интеграция FastAPI с модульной маршрутизацией.
- [x] Клиент Росреестра: получение полных данных в JSON с разгадыванием капчи (ML модель).
- [x] Конвертер Росреестра: перевод XML в официальный PDF через ЛК Росреестра.

- [x] Управление зависимостями и исправление ошибок окружения.

## 🗺 Фаза 2: Интеграция с НСПД (Завершено ✅)
*Цель: Обогащение данных объекта точными пространственными координатами и полигонами.*

- [x] **Реализация клиента НСПД:**
    - Создание `app/services/nspd_client.py`.
    - Реализация запросов к API НСПД по кадастровым номерам.
- [x] **Обработка геометрии:**

    - Реализация расчета центра (центроида) для точек и полигонов.
    - Поддержка типов геометрии Point и Polygon.
- [x] **Эндпоинты НСПД API:**
    - Создание `app/api/nspd.py`.
    - Реализация агрегированного метода `GET /nspd/property/{cad_num}` со сбором данных по категориям (Здания, ЗУ, Помещения).
- [ ] **Интеграция GeoPandas и Shapely (Отложено):**

## ⚖️ Фаза 3: Интеграция с ФИАС и СУДРФ (Завершено ✅)
*Цель: Автоматическое определение судебного участка, к которому относится объект недвижимости, через связку ФИАС → СУДРФ.*

- [x] **Интеграция с ФИАС (`app/services/fias_client.py`):**
    - Получение мастер-токена через `GetSpasSettings`.
    - Поиск `ObjectID` по кадастровому номеру (`GetObjectsByCadastralNumber`).
    - Получение подсказок адреса (`GetAddressHint`) с предварительной очисткой адреса.
    - Получение детальных сведений об объекте по `ObjectID` (`GetAddressItemById`).
- [x] **Интеграция с СУДРФ (`app/services/sudrf_client.py`):**
    - Получение списка судов по FIAS GUID (`getCourtListByFiasCode`) с фильтрацией по коду региона (`VNKOD`).
    - Fallback-поиск `fias_id` по адресу через сервис подсказок sudrf.ru.
- [x] **Очистка адресов (`app/services/address_cleaner.py`):**
    - Нормализация адресных строк: удаление квартир, помещений, служебных пометок перед поиском в реестрах.
- [x] **Логика сопоставления:**
    - Алгоритм определения суда: кадастровый номер/адрес → ФИАС GUID дома → СУДРФ → судебный участок, с fallback по текстовому адресу.
- [x] **Эндпоинты API (`app/api/fias.py`, `app/api/sudrf.py`):**
    - ФИАС: `/fias/by-cadastral/{cad_num}`, `/fias/search-address`, `/fias/by-object-id/{object_id}`, `/fias/object-id/{cad_num}`.
    - СУДРФ: `/sudrf/by-cadastral`, `/sudrf/by-address`, `/sudrf/by-object-id`.

## 📄 Фаза 4: Аналитические PDF-отчеты (Текущий приоритет 🚀)
*Цель: Создание кастомного информативного отчета, объединяющего все источники данных: Росреестр, НСПД, ФИАС и СУДРФ.*

### Уже сделано (заготовка)
- [x] **`app/services/pdf_service.py`**: класс `PDFService.generate_report` и `format_timestamp`.
    - Сейчас пишет текстовый «превью» вместо PDF (заглушка до внедрения ReportLab).
    - Разобраны поля Росреестра: кадастровый номер, адрес, площадь, этаж, стоимость, права, обременения.

### Рефакторинг (выполнено)
- [x] **Вынесен справочник типов судов в `app/services/types/court_types.py`**:
    - Единый источник правды `COURT_TYPES` (код → русское название) и производный `COURT_TYPE_ORDER`.
    - `pdf_service.py` и `sudrf_client.py` импортируют справочник вместо дублирования кодов `MS/RS/OS/AJ/KJ/GV/OV/AV/KV/VS`.
    - Helper `court_type_label()` инкапсулирует fallback-логику (код → русское название, иначе «Суд»).

### Дизайн шаблона отчета
- [x] **Макет на `ReportLab`** (единый фирменный стиль: шапка, колонтитулы, нумерация страниц).
    - Разделы:
        1. **Общая информация** — кадастровый номер, тип объекта, адрес, площадь, кадастровая стоимость.
        2. **Пространственные данные** — координаты (WGS 84) и текстовое описание геометрии (без карты/схемы в первой итерации).
        3. **Правовой статус** — права, обременения, ограничения (из Росреестра).
        4. **Судебная принадлежность** — судебный участок (из СУДРФ).
        5. **Сведения ФИАС** — нормализованный адрес, ObjectID, иерархия адреса.
    - Пустые секции отображаются с пометкой «данные недоступны» (не пропускаются).
- [x] **Поддержка кириллицы** (регистрация TTF-шрифта DejaVuSans в ReportLab) и таблиц.

### Сервис агрегации данных
- [x] **`app/services/report_service.py`** — оркестрация источников:
    - Параллельный сбор: async-клиенты (`RosreestrClient`, `NspdClient`) через `asyncio.gather`; sync-клиенты (`FIASClient`, `SudrfClient`) через `asyncio.to_thread`.
    - Слияние в единую структуру отчета (normalized report dict).
    - Обработка частичных сбоев: источник недоступен → секция с пометкой «данные недоступны», отчет собирается из остальных.
- [x] **Границы источников**: Росреестр — ядро отчета; НСПД/ФИАС/СУДРФ — опциональны.

### Генератор PDF

    - Возврат PDF-файла (`application/pdf`).

## 🧪 Фаза 5: Аутентификация и авторизация API (Завершено ✅)
*Цель: Ограничение доступа к API и разграничение прав пользователей.*

- [x] **Аутентификация пользователей:**
    - Регистрация (`POST /auth/register`) и вход (`POST /auth/login`) с выдачей JWT.
    - Хранение учётных данных и хешей ключей в PostgreSQL (пароли — Argon2, ключи — SHA-256).
- [x] **Управление API-ключами:**
    - Выдача (`POST /auth/api-keys`), активация/деактивация (`PATCH`) и отзыв (`DELETE`).
    - Привязка ключа к пользователю; полный ключ показывается один раз.
- [x] **Защита эндпоинтов:**
    - JWT (Bearer) или активный API-ключ (`X-API-Key`) для **всех** методов, **кроме** `POST /converter/xml-to-pdf` и `/auth/*`.
    - FastAPI-зависимости `require_auth` / `require_admin`.
- [x] **Разграничение прав (роли):**
    - Роли `admin` / `user`; админ-эндпоинты `/admin/*`.
    - Суточная квота запросов для `user` (`DEFAULT_DAILY_QUOTA`, per-user `request_limit`), `429` при превышении.
- [x] **Инфраструктура**: PostgreSQL в docker-compose, SQLAlchemy (async) + asyncpg, Alembic-миграции.

## 📋 Технические заметки
- **Версия Python:** 3.10 (Строго)
- **Критические зависимости:** `tensorflow-cpu`, `pdfkit` (требует системный пакет `wkhtmltopdf`).
- **Конфиденциальность:** Хранение ключей API в файле `.env`.
- **Доступ к API:** Все методы требуют авторизации и активного API-ключа, кроме конвертации XML в PDF (`POST /converter/xml-to-pdf`), которая остаётся публичной.
