# Дорожная карта проекта: TerraData

## 🎯 Цель проекта
Создание комплексной системы анализа недвижимости, которая получает данные из Росреестра, переводит XML-выписки в официальные PDF, а также обогащает информацию данными из НСПД (пространственные данные) и определяет принадлежность объекта к конкретному судебному участку.

---

## 🛠 Фаза 1: Инфраструктура и Базовое API (Завершено ✅)
- [x] Настройка структуры проекта (`app/`, `data/`).
- [x] Интеграция FastAPI с модульной маршрутизацией.
- [x] Клиент Росреестра: получение полных данных в JSON с разгадыванием капчи (ML модель).
- [x] Конвертер Росреестра: перевод XML в официальный PDF через ЛК Росреестра.
- [x] Dockerизация: стабильное окружение на базе Python 3.10-bookworm.
- [x] Управление зависимостями и исправление ошибок окружения.

---

## 🗺 Фаза 2: Интеграция с НСПД (Текущий приоритет 🚀)
*Цель: Обогащение данных объекта точными пространственными координатами и полигонами.*

- [x] **Реализация клиента НСПД:**
    - Создание `app/services/nspd_client.py`.
    - Реализация запросов к API НСПД по кадастровым номерам.
- [x] **Обработка геометрии:**
    - Создание `app/services/coords_converter.py` для перевода координат EPSG:3857 $\rightarrow$ EPSG:4326.
    - Реализация расчета центра (центроида) для точек и полигонов.
    - Поддержка типов геометрии Point и Polygon.
- [x] **Эндпоинты НСПД API:**
    - Создание `app/api/nspd.py`.
    - Реализация агрегированного метода `GET /nspd/property/{cad_num}` со сбором данных по категориям (Здания, ЗУ, Помещения).
- [ ] **Интеграция GeoPandas и Shapely (Отложено):**
    - Перевод в низкий приоритет. Будет реализовано при необходимости сложного пространственного анализа.

---

## ⚖️ Фаза 3: Определение судебных участков
*Цель: Автоматическое определение суда, к которому относится объект недвижимости.*

- [ ] **Механизм определения юрисдикции:**
    - Реализация поиска через базу знаний (сопоставление адреса/района с реестром судов).
    - Интеграция с данными ФИАС для определения кода судебного района (sudrf).
- [ ] **Логика сопоставления:**
    - Создание алгоритма определения суда на основе иерархии адреса (Регион $\rightarrow$ Район $\rightarrow$ Город $\rightarrow$ Судебный участок).
- [ ] **Эндпоинты API судов:**
    - Создание `app/api/courts.py` для получения информации о суде по кадастровому номеру.

## 📄 Фаза 4: Аналитические PDF-отчеты
*Цель: Создание кастомного информативного отчета, объединяющего все источники данных.*

- [ ] **Дизайн шаблона отчета:**
    - Разработка макета с использованием `ReportLab`.
    - Разделы: Общая информация $\rightarrow$ Пространственные данные (Карта/Координаты) $\rightarrow$ Правовой статус $\rightarrow$ Судебная принадлежность.
- [ ] **Сервис агрегации данных:**
    - Создание сервиса, который оркестрирует вызовы `RosreestrClient`, `NspdClient` и `CourtService`.
- [ ] **Эндпоинт аналитического PDF:**
    - `POST /analytics/generate-report` $\rightarrow$ Генерация расширенного PDF с обогащенными данными.
